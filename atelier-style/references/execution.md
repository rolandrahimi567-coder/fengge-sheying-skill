# Execution boundary

Version 0.2 replaced the old coarse soft-portrait / any-prop bins with narrow relationships. 300 images were screened on contact sheets; 18 selected images were checked at larger sheet scale against source evidence. This is assistant review, not human acceptance or complete full-resolution annotation.

The original three recipes each have four references and two held-out inputs. Version 0.3 adds seven recipes with four references each; their output tests are not yet scheduled. Some references belong to related shoots; do not treat them as four independent confirmations. Held-out means not used to write common recipe rules; inspecting an input for suitability is allowed. Individual edits must not leak into shared recipes to overfit the test.

The full index includes B/B1, versioned garment V3.1 candidates and available aesthetic history with identity/hash checks. Historical prose is only hypothesis evidence. The source audit explicitly records unsupported claims and missing data.

At external execution, freeze model ID, provider, image size, quality and budget before either arm. Both arms get the same authorized input and reference assets. The baseline shares the task and preservation requirements but not recipe-specific steps. Blind labels should not expose arm names. Store actual provider receipts, failures and elapsed time; blank cost is not zero. Do not retry failed arms automatically or drop them from reported outcomes.

No provider calls have been made by this revision. API cost for this revision is zero; future generation cost and quality are unknown. A readable prompt is not a generated image, and a passing validator is not visual acceptance.

Version 0.3 reuses the frozen v0.2 source snapshot, screens all 300 contact thumbnails again, and inspects 28 new references on enlarged sheets. It does not claim current database completeness or per-pixel image auditing. 183 images have one or more provisional associations and 117 remain unassigned. `recommend` reads those associations and never changes the application retrieval system. Output treatments remain separate and deferred.

Version 0.4 routes discovery through eight user-specified style directions; ten methods remain subordinate. New daily/natural and soft/atmospheric cards are candidate-only. Three first-pilot priorities are not a claim of strongest measured performance. Previous test artifacts remain historical and have not been rerun.
