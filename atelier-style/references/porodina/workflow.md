# Porodina 研究与实验编译流程

当前生图链路视为正式编译流程。编译器把已经完成的人工看图与参考选择编译成标准 imagegen 任务；它不替代视觉判断、不自动调用生图，也不把成功返回当作风格通过。

## 编译顺序

1. 把用户原话完整保存为 UTF-8 文本。确定本次题材、景别、动作、服装、数量，以及采用旧分类还是研究轴。
2. 读取本文件、feedback-policy.md、reviews.json、相关 feedback-ledger.jsonl 条目和 branches.json。通过 reference-index.json 打开候选原作完整大图，记录实际观察。
3. 选择一张摄影原作；只有完整看图确认风格一致时才选择两张。两张输入必须显式记录 `pair_consistency=confirmed`。分类只负责检索，不构成一致性证明。默认另选一张服装参考；用户明确不要时记录本次覆盖原因。
4. 分别写中文摄影参考计划和服装参考计划。摄影原作控制构图、人物大小与方向、视线、空间、光色、遮挡、虚实、运动与材料受光关系；服装参考只控制服装轮廓、结构、材料、工艺与用户指定颜色，不控制模特身份、姿势、构图、背景、灯光或整体调色。两类参考冲突时优先遵守用户题材，并保持职责分离。
5. 运行 `scripts/prepare_porodina_generation.py`。检查输出中的原作路径、哈希、输入顺序、参考职责和中文提示词；随后按 `tool_arguments` 原样调用内置 imagegen。
6. 保存任务、实际提交的参考图、结果或错误回执。画廊按输入顺序并列展示生成图、参考图和中文提示词。工具成功、助手观察和用户评价分别记录。
7. 用户评价回写 feedback ledger 和 reviews。只有经过多个新题材与景别人工验收的方法，才能从实验候选升级为可复用配方。

每个编译任务只对应一张输出。多题材或多张测试要分别编译独立任务，使每张结果都能追溯到自己的用户要求、参考图和提示词，不能共用一个含混的批次记录。

单参考编译示例：

```sh
python scripts/prepare_porodina_generation.py \
  --request-file REQUEST.txt \
  --category 动作拖影与多重人像 \
  --axis material-traces \
  --photo-ref 082 \
  --selection-reason '原作的运动重叠与本次动作方向相符' \
  --inspection-file INSPECTION.txt \
  --reference-plan-file REFERENCE_PLAN.txt \
  --clothing-reference CLOTHING.jpg \
  --clothing-plan-file CLOTHING_PLAN.txt \
  --out JOB.json
```

双摄影参考必须增加 `--pair-consistency confirmed`。用户明确不要服装参考时，以 `--no-clothing-reference-reason '用户明确要求仅用摄影参考'` 记录本次覆盖。用户明确指定选角时使用 `--explicit-casting`；用户明确需要与原作不同的墙壁或建筑时使用 `--background-override`。这些开关只记录本次明确需求，不改变长期默认。

先读取 feedback-policy.md、visual-language.md 的完整画面表达及 reviews.json；相关原话查 feedback-ledger.jsonl；需要定位原作时再查 branches.json。reference-index.json 保留150张的真实本地路径、哈希、来源和此前观察。若原图路径失效，按已记录来源或资产位置重新定位并核对哈希，不以缩略图代替细节检查。

## 保留用户意图

高饱和、艳丽、虚幻与真实人物摄影并存；不得靠去色、取消虚幻或隐藏脸来伪装改善。后续生成不使用亚裔女性，除非用户明确覆盖此偏好；不从原图面孔猜测族裔。每次使用一张或两张风格原作：两张风格一致才同时输入，否则只使用最适合需求的一张；编辑目标不算风格参考。批量探索覆盖近景肖像、全身、坐姿与环境人物；单次采用用户要求的景别，不强塞全部景别。

## 参考风格一致性优先

先查看完整原图，比较色彩与明暗组织、人物和材料质感、虚实关系、运动或重叠的视觉表达。只有风格一致时才使用两张；不一致则只选最适合当前需求的一张。不为补充姿态、构图或凑数量而混用不同风格。同属某分类、都有人物运动、同一摄影师或项目都不能替代视觉判断；同风格也不要求相同动作或景别。两张一致的原作可以各有侧重。

用户明确示例（2026-09-16）：082 + 147 风格不同，不再作为双参考组合；138 + 141 风格一致，可以共同使用。前者若单独选择，不预设永久只选其中某张，按具体需求判断。此反馈不能推断为用户已接受对应生成结果。

## 人物真实感

保持高饱和、艳丽与虚幻，同时让面部、手部、身体承重和衣料接触更可信。中文提示词按画面需要简洁加入：皮肤有自然且不均一的细微纹理与色泽，面部保留轻微不对称和自然表情，局部高光随骨骼与皮肤起伏变化；手指关节、支撑脚、身体压住衣物处的褶皱符合动作。避免统一磨皮、蜡质反光、过分规则的五官和玩偶般眼睛。不要把粗糙颗粒、夸张毛孔、去色或全脸锐化当作真实感，也不要强制取消原作的柔化与重影。这是待测试的改善要求，不宣称已验证有效。

## 组织请求

保存用户原话。另存内容需求、连贯的完整画面描述、参考角色、必要限制。优先组织服装、姿态、构图、光色与材质的共同作用，不把测试缩减为单个特效是否出现。不要自动把全部八个维度拼进长提示词；不要强加红衬衫紫裙、转身、橙蓝光、主脸最锐利或全局哑光肤质。用户未指定内容时，选简单的新题材并记录为助手设计。

请求建议结构：用户题材与景别；摄影师姓名与连贯的整体视觉描述；实际选用原图的作用；用户必要限制。具体拍摄参数仅在有来源或用户指定时使用。

## 实验及验收

固定使用当前内置 imagegen 并遵守图像工具流程。用户明确不要换工具，不主动开展其他供应商对照。普通请求按请求数量生成；明确探索时按本次约定选择有边界的多题材批次，用户已多次要求不只一两张；保留失败和回执，不质量重抽。两张均被用户否定则暂停这套具体配方，复核差异后再决定下一次；不是永久禁止整个视觉维度。

助手观察与用户评价分开。评价内容适配、摄影质感、主要关系、构图、材料与身体、复制风险；不自动编造分项分数。可接受、勉强、拒绝、未评价分别存储，勉强不是通过。用户只给批次评价时按批次记录，不能推断底图或每个问题的评分。

候选得到认可后再换题材和景别检验迁移；至少要有多个新题材的人工作品验收，才能标记为可复用方法。先约定测试范围，不能自动启动无限生成。没有通过的方法保持实验状态。

## 当前边界

不存在成熟配方。01/D2是半身实验的勉强候选，不能直接推广。全身一次生成与两步法四张最终结果均被否定。该红衬衫紫裙连续亮尾迹配方暂停，不代表所有编辑路径无效。

花卉身体融合早期被拒，后因用户明确要求第四类而恢复实验，不是质量通过；避免批次全是花。超现实道具旧失败保留，巨大钥匙与超能力式道具仍为已拒方向。详见 feedback-policy.md 的规则沿革。

本文件是知识组织，不是权重训练。若结构清楚的多题材实验仍反复失败，记录生成能力限制，不能靠加长skill声称完成风格蒸馏。

## 背景遵循参考原图

用户反馈（2026-09-16）：生成的墙壁太假，原参考图没有的墙不要生成。默认不得自行补入墙壁、混凝土通道或建筑空间；先检查原图背景，平面色底、影棚背景或抽象色面不能擅自解释成实体墙。保留参考中实际可见的背景形式与空间复杂度。只有用户明确提出墙壁或建筑需求时才按该次需求处理。不要为了环境人物或增加真实感而编造建筑。
